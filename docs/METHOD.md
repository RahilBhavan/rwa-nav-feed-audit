# Issuer-history method

## Gate and scope

The brief requires at least three products with publicly retrievable issuer fund NAV history. Count a product once when public, keyless retrieval yields multiple dated observations of the same instrument's USD NAV per share or token from its issuer, fund manager, administrator, or authorized publisher such as a transfer agent. The reference needs to stand on its own as a fund valuation record. A paper trail hosted on EDGAR qualifies when the issuer filed it. A vendor dashboard, an index of the oracle's own reports, a market quote, a stable value target, and portfolio-level NAV without the matching class denominator do not qualify. USTB and BENJI/FOBXX meet this strict definition, for **2/6**. The broader screen counts **3/6** by including dated USDY LLC note principal per token. These benchmarks apply to different instruments and retain their own valuation definitions.

The product statuses in `tests/evidence/manifest.json` are manual research classifications based on the cited source review. The script replays those classifications and counts them. A successful live fetch or row comparison has no bearing on whether a source qualifies. The USDY note sample is recorded in the results and was reviewed manually. The automated USDY comparison covers only the product chart.

This is a source-availability gate. The valuation date, date displayed by a chart, issuer publication time, filing acceptance time, and eventual oracle update time are different clocks. We preserve the available date label and make no publication-time inference. The run uses no chain data, inferred supply, address matching, or forward fills. An issuer statement describes publication practice. A prospectus or offering notice identifies terms. Calculated counts and comparisons are arithmetic. Oracle references in the source notes describe the vendors' claims. Gate eligibility is our interpretation.

## Retrieval and extraction

- **USTB.** Confirm fund ID 1 and CUSIP 86851T204 on Superstate's symbol endpoint. The fund page lists Invesco Advisers, Inc. as investment manager, Superstate Services LLC as transfer agent, and NAV Fund Services as NAV calculation agent. The public OpenAPI describes the numeric ID and inclusive date filters for `GET /v1/funds/{id}/nav-daily`. Use `net_asset_value` with `net_asset_value_date` and validate fund ID 1 on each row. The asset page and `historical_data.nav` on the fund page API identify the scale as USD per share. The financials endpoint distinguishes official NAV from indicative continuous pricing. Preserve weekend and holiday date labels as published. At capture, the latest official NAV was dated 2026-11-24 and the daily history repeated its value through 2026-11-26. Treat November 25 and 26 as provisional carry-forward labels. [Superstate sources](SOURCES.md#ustb)
- **BENJI.** The fund's EDGAR filings give series `S000067043`, class `C000215714`, ticker FOBXX. Franklin maps one FOBXX share to one BENJI. Read `formData/classLevelInfo` for that class in the September and October 2026 Form N-MFP3 XMLs. Read the date/value inside each `dailyNetAssetValuePerShareClass` block. Item B.6 defines market-based NAV per share at business-day close, rounded to four decimals for a dollar fund. The dates are valuation dates. Filing indices provide a separate acceptance time. The issuer's pricing page distinguishes market-based NAV from amortized-cost NAV used for dealing. [Franklin and EDGAR sources](SOURCES.md#benji)
- **USYC.** Read `price` and Unix `timestamp` from the published `usyc_price_report` JSON. Preserve the decimal price as supplied and render the timestamp in UTC. The report timestamp is the oracle reporting clock. The portal explicitly indexes onchain reports. [Circle/Hashnote sources](SOURCES.md#usyc)
- **OUSG and USDY.** Fetch the issuer product HTML and decode the JSON embedded in its `self.__next_f.push` script elements without executing them. Use `assetData.symbol` to identify the instrument and `history[].asset.priceUsd` with `history[].timestamp` for the chart series. Read numeric literals as decimals. The dates in the replay are midnight UTC chart buckets. OUSG administrator PDF packets are also retrievable from the app's November 2026 reporting page. The checked packets contain fund-wide NAV in USD and lack a usable NAV/share field or matching offchain units outstanding. For USDY, the issuer's public daily report archive yields a dated end-of-day token principal in Section C. The notes identify the report issuer and keep it distinct from the website chart and backing assets. [Ondo sources](SOURCES.md#ousg)
- **BUIDL.** Compare the product listing and launch release with Form D/D-A and the transfer agent's financial statements. Check the BNY administrator guide against RedStone and Chronicle product sources. The guide describes publishing class-level NAV on Ethereum and does not identify an independent public offchain archive. No synthetic daily $1 series is used. [BUIDL sources](SOURCES.md#buidl)

## Offline evidence and live verification

`tests/evidence/manifest.json` records the source URLs, windows, original response hashes and selected non-SEC observations in a common date/value format. The retained BENJI excerpts contain the filed class NAV blocks and identifiers. The offline replay verifies those two fixture digests, parses the XML and combines its rows with the selected observations. Live tests use generated wire-format stubs for non-SEC endpoints.

Use the replay, tests and retrieval commands in [Run it](../README.md#run-it). The retrieval script stores current non-SEC sources and hash receipts under ignored `data/sources/`. The archived USDY report members can also be extracted there from the issuer's ZIP. [Source capture hashes and archive instructions](SOURCES.md#download-and-capture-hashes)

With a genuine EDGAR User-Agent supplied by the caller, the live command records the current UTC access date separately from the pinned access date. It fetches the seven series with a 2 MB response limit and a 12-second socket timeout per request. Each fixed window has a `comparison` against the matching recorded observations by full observation label and extracted decimal string, with missing labels, added labels, and pinned/live values for changes. USYC reports the latest three available observations with a separate `rolling_window` because its API rolls. Each series records `fetch_status` and any request or extraction error. Live prints the full report, preserving other sources' results, and exits 1 for any source error or fixed-window difference. A successful comparison can exit 0 while the pinned research gate still fails.

For the OUSG cross-check, use `pdftotext -layout FILE -` on the linked November 23 account statement. Under Statement of Changes in Net Asset Value, use Period to Date figures to divide net income by beginning balance plus additions less redemptions. Compare the result with the percentage change between the November 23 and 24 UTC chart buckets. The formula gives an implied accounting return for the period. It can check daily changes, while per-unit levels and the path by which data reaches the chart require separate evidence. [Calculation](RESULTS.md#ousg-return-cross-check) · [Primary sources](SOURCES.md#ousg)

For USDY, extract the named May 2025 reports using the source register. Run `pdftotext -layout data/sources/usdy-2025-05-02.pdf -` and read the Reference Token row in Section C. Repeat for May 5, 6 and 9. The ZIP ordering and public chart serialization can change. [Archive and report hashes](SOURCES.md#usdy-llc-daily-report-archive)

There are no pinned blocks or contract reads in this slice. The source registry records oracle documentation only where it resolves provenance.
